# DXギルド

> ひとりの成功を、みんなの成果に。

IT Div. の中で、**困りごと**（手作業・時間を取られていること）と、
**解決策**（ノーコード・ローコード・AI エージェントでこう解いた）を共有し、
よそのチームへ**横展開**するためのギルド（コミュニティ）。

まだ悩みの段階でも始められる。**成功事例を探し**、なければ **AI の「賢者」と壁打ちして解決策を企画し**、
結果を待たずに**挑戦中から共有して仲間を募り**、成功したら**成功事例として広げる**。
うまくいかなかった挑戦も**学び**として残る。その行いが経験値になり、管理者は成果を数字で見られる。

### 投稿の段階

```
困りごと（クエスト） → 挑戦中 → 成功事例 → 横展開
                          └→ 学び（うまくいかなかったことを、次に試す人へ）
```

| 段階 | 押せるボタン | 時間の数字 | 横展開 |
|---|---|---|---|
| 挑戦中 | 一緒にやりたい | 減る**見込み** | まだできない |
| 成功事例 | うちでも使いたい | 実際に**減った**時間（報告のときに置き換える） | できる |
| 学び | 参考になった | 数えない | できない |

挑戦した本人が、詳細の画面の「結果を報告する」で、成功事例か学びに変える。
**減った時間・金額・クエストの報酬は、成功事例だけで数える**（挑戦中の時間は見込みなので足さない）。

いまは**ローカルで動かす試作**（v0.3）。ログインは無く、右上で「だれとして使うか」を選ぶ。
社内ハッカソンの応募文は [`docs/hackathon.md`](docs/hackathon.md)。

---

## なぜ作るか

- 困りごとに気づいても、自分でアイデアを出して解決策を考えるのは難しい
- 困りごとと解決策が、グループ・チームの中に閉じている
- 別のチームが、同じことを別々にやっている（同じ困りごと、同じ仕組みの作り直し）
- どれだけの時間が失われ、どれだけ減らせたのかが見えない

## できること（v0.3）

| 画面 | 中身 |
|---|---|
| ホーム `/` | 横展開マップ・数字・**報酬つきの挑戦者待ちクエスト**・**いま挑戦中（仲間募集）**・いま広がっている成功事例・新着 |
| クエスト `/explore` | すべて／困りごと／挑戦中／成功事例／学び／挑戦者待ちのタブと、キーワード・分類・ツール・チームの絞り込み。新しい順／反響順／時間の大きい順 |
| 投稿の詳細 `/posts/[id]` | 困りごと：「うちも困っている」・挑戦と事例・**報酬（XP）**・賢者の工房への入口 ／ 挑戦中：「**一緒にやりたい**」・本人だけの「**結果を報告する**」 ／ 成功事例：「うちでも使いたい」・「横展開した」・**年あたりの金額** ／ 学び：「参考になった」 ／ 共通：コメント・似ている投稿 |
| 投稿する `/new` | 困りごとと挑戦・解決策を一つのフォームで（段階の既定は挑戦中）。**効果の試算**（回数×時間×人数×削減率）と、**AI の見積もり** |
| **賢者の工房** `/forge` | 悩みをひとこと書くと、**AI の賢者が質問で掘り下げる**。「企画書にまとめる」で、**あるべき姿・問題・課題・解決策の案（実現方法・ステップ・効果の試算・インパクトの道筋・リスク）・明日からの一歩**の企画書になる。右に社内の似た事例。**ワンクリックで挑戦として共有**（困りごと＋解決策の「挑戦中」の二つの投稿） |
| ギルド `/teams` | 横展開マップ（大）と、チームごとの数 |
| ランキング `/ranking` | 自分のレベル・称号・バッジ、冒険者とギルド（チーム）のランキング、経験値のもらい方 |
| **司令室** `/admin` | 管理者向け。困りごと・挑戦中・成功事例・学び・減った時間・金額換算・動いた人数、週ごとの投稿、**悩みが成果になるまで**（対話 → 企画書 → 挑戦 → 成功 → 横展開）、優先して手を打つべきクエスト、分類ごと・ツールごと |

### 経験値（XP）

記録から毎回数え直す（XP の表は持たない）。数え方は `src/lib/game.ts` の `XP_RULES`。

| 行い | XP |
|---|---|
| 困りごとを出した | +10 |
| 挑戦を共有した（段階を問わず、解決策の投稿ごと） | +15 |
| 挑戦が成功し、成功事例になった | +30 |
| うまくいかなかった挑戦を、学びとして残した | +10 |
| よその困りごとを成功事例で解決した（クエストの報酬） | 20 ＋ 共感×5 |
| 自分の解決策が、よそのチームに横展開された | +50 |
| よそのチームの解決策を取り入れた | +20 |
| 賢者と企画書をまとめた | +15 |
| 「うちも」「一緒に」「使いたい」「参考になった」をもらった | +3 |
| それらを押した | +1 |
| コメントした | +2 |

バッジは8つ（はじまりの依頼・挑戦者・依頼達成・伝道師・越境者・賢者の弟子・共感の灯・語り部）。

### 効果の試算

**数字の計算は AI にさせない。**AI が出すのは前提（月の回数・1回の分・人数・削減率）だけで、
計算はコード（`calcEffect`）がする。金額は「減った時間 × 時間単価（既定 5,000円）」。

## 動かし方

Node.js 22 以上。リポジトリの一番上で：

```powershell
npm install
```

```powershell
npm run dev
```

http://localhost:3000 を開く。

- DB は `data/dx-guild.db`（SQLite・git に入れない）。**初めて開いたときに、見本データで作られる**
- 見本データに戻したいとき：開発サーバーを止めてから `npm run db:reset` → もう一度 `npm run dev`
- 確かめ：`npm run typecheck` ／ `npm run lint`

### AI（賢者）をつなぐ

AI は **GEMu_Web と同じ OpenAI の API**（`chat.completions`）を使う。
`.env.example` を写して `.env.local` を作り、`OPENAI_API_KEY=` のあとに OpenAI の API キー（`sk-` で始まる）を入れて、開発サーバーを起動し直す。

```powershell
Copy-Item .env.example .env.local; notepad .env.local
```

- **鍵が無くても動く。**そのときの賢者は「デモ」の決まった返事をし、画面にもデモと出る
- モデルは GEMu_Web と同じ `gpt-4.1-mini`（`DXG_MODEL` で替えられる）。gpt-5 以降の考えるモデルに替えるときは、`DXG_REASONING_EFFORT` で考える量も決められる
- 企画書と見積もりは、OpenAI の「決まった形で返す」機能（Structured Outputs）で受け取り、さらに zod で確かめる
- 時間単価は `DXG_HOURLY_COST`（円）

## 作り

| | |
|---|---|
| 画面とサーバー | Next.js 16（App Router・Server Actions）＋ TypeScript |
| DB | SQLite（better-sqlite3）。表の定義は `src/lib/db.ts`、見本データは `src/lib/seed.ts` |
| AI | OpenAI（`openai` パッケージ）。壁打ちは流しながら返す（streaming）、企画書と見積もりは形を決めて受け取る（Structured Outputs ＋ zod） |
| 見た目 | 手書きの CSS 一枚（`src/app/globals.css`）。頭に考え方を書いてある |

```
src/
  app/
    forge/          賢者の工房（一覧・対話と企画書）
    ranking/        ランキング
    admin/          司令室
    api/forge/[id]/ 壁打ち（chat）と企画書（plan）
    api/estimate/   効果の見積もり
  components/       カード（PostCard）・横展開マップ・対話・企画書・効果の試算・グラフ
  lib/
    db.ts           DB を開く・表の定義
    seed.ts         見本データ（チームも人も架空）
    data.ts         読み出し（画面から呼ぶ）
    actions.ts      書き込み（投稿・リアクション・横展開・結果の報告・コメント・工房の開始と共有）
    ai.ts           賢者のプロンプトと、OpenAI の呼び出し・デモの返事
    forge.ts        工房の対話の読み書き・社内の似た事例を探す
    game.ts         経験値・レベル・称号・バッジ・ギルド
    admin.ts        司令室の集計
    constants.ts    分類・ツール・段階・効果の計算
```

## 見た目の考え方

- **明るい地**（ごく薄い緑がかった灰色）に、**黒い字**と**緑の差し色**。困りごとは青緑
- 構造は **1px の罫**でつくる。角丸は 2px。浮かせるのは触れたときだけ
- 近未来の手ざわりは、**方眼の地・四隅の目印・等幅の英字の見出し・線を流れる点**で出す
- RPG らしさは言葉（クエスト・賢者・ギルド・司令室）と、紋章・バッジの形で出し、絵は足さない
- 字は IBM Plex Sans JP（和文）と IBM Plex Mono（数字・英字）

## 次に考えること

- ログイン（社内に出すなら Entra ID など）。いまの「人の切り替え」は試作のためだけ
- 社内で使える AI に替える（Azure OpenAI なら、`ai.ts` の接続先を替えるだけで済む作り）。呼び出しは `src/lib/ai.ts` に集めてある
- 置き場所（社内のサーバー・Azure など）と、それに合わせた DB
- 似た事例の探し方を、言葉の重なりから意味で探す形（埋め込み）にする
- 解決策の「中身」の受け渡し（フローのパッケージ・プロンプト集などのファイルを添える）
- 通知（自分の困りごとに挑戦が始まった・「一緒にやりたい」が付いた・自分の成功事例が横展開された）
- 「一緒にやりたい」を押した人を、挑戦の仲間（共同の投稿者）として載せる
